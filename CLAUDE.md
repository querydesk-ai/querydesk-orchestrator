# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

**QueryDesk orchestrator** — the Python/FastAPI half of an internal AI service desk for an insurance
company. It answers questions the knowledge base covers (citing the source article) and turns action
requests into correctly categorised Service Requests (SRs) it tracks to closure.

The authoritative spec is `../../SR Resolution Bot — Final PRD & 10-Day Roadmap.md`. **Read it before
making design decisions** — it supersedes the older "Phase 0 / Phase 1" framing that earlier versions
of this repo used. The current task breakdown lives in [docs/task.md](docs/task.md).

QueryDesk is two services behind one contract:

| Repo | Contents | Owner |
| --- | --- | --- |
| `querydesk-orchestrator` | **this repo** — FastAPI, RAG, router, decision layer, Celery, chat page | Tanmay |
| `querydesk-ticketing` | Spring Boot 3 / Java 21 ticketing service, migrations, webhook outbox | Partner |
| `querydesk-docs` | PRD, OpenAPI contract, `categories.json`, eval set | Both |

**Contract first:** no endpoint or field change without a PR in `querydesk-docs` approved by the
other person. The orchestrator never reaches into the ticketing service's database — only its API.

## Commands

The package uses a `src/` layout (`src/querydesk`) and is managed with **uv**: `uv sync` builds
`./.venv` from `uv.lock` (Python from `.python-version`, dev group included). pytest also sets
`pythonpath = ["src"]`, so tests import the package without an install.

```bash
uv sync                                     # install / update .venv from uv.lock
uv add <pkg>  /  uv add --dev <pkg>         # add a dependency (updates pyproject + uv.lock)

uv run pytest -q                            # full suite; offline, no API key
uv run pytest tests/unit/test_chunking.py -q
uv run pytest tests/unit/test_rag.py::test_no_hits_escalates_without_calling_the_llm -q
uv run ruff check . --fix                   # lint (CI runs it)
uv run ruff format .                        # format (CI runs `ruff format --check`)

uv run scripts/check_services.py            # Qdrant / Redis / Postgres reachability
uv run scripts/ingest.py --recreate         # re-index data/kb into Qdrant
uv run scripts/eval_run.py                  # 60-query eval vs live services -> eval/results/
uv run scripts/eval_report.py               # proposals + docs/eval-report-v0.md (never edits config)

uv run uvicorn querydesk.main:app --reload
```

Dependencies live in `pyproject.toml` + `uv.lock` only — no `requirements.txt`. Commit `uv.lock`
with every dependency change; CI runs `uv sync --locked` and fails if it is stale.

The test suite must stay fully offline — mock Fireworks with `respx`, monkeypatch the embed and
search functions. A test that needs a live API key or a live Qdrant does not belong in `tests/`.

## Architecture

Request flow for `POST /chat`: if a slot-filling conversation is open in Redis the message fills
missing fields; otherwise hybrid retrieval returns top KB chunks and the router returns the top two
categories. The decision layer picks one decision + `resolution_type`. Answers are generated by
Fireworks from the retrieved chunks; SRs go to the ticketing service with an idempotency key.
Everything after SR creation is async (webhook → Redis → Celery).

### Module conventions

- **One module owns each external dependency**, and nothing else may talk to it directly:
  `services/llm/fireworks.py` (LLM + embeddings), `services/retrieval/qdrant_store.py` (vector
  search), `services/retrieval/sparse.py` (BM25). Each raises a subclass of `UpstreamError`
  (`core/errors.py`), and the routers map that whole family to HTTP 502 in one place.
- **`core/config.py` is the only reader of the environment.** Nothing else touches `os.environ`;
  import the shared `settings` instance instead of re-instantiating `Settings`.
- `services/rag.py` orchestrates retrieval + generation. It is a function the decision layer *calls* —
  routing rules do not go in it.
- `services/retrieval/query.py::embed_query_vectors()` embeds a message **once**; pass the result to
  both `rag.answer(vectors=...)` and `routing/router.route()`. Embedding is the slowest step (~2 s).
- `services/routing/router.py` reports the top-two categories and whether it is confident; it never
  decides answer-vs-SR — that is the decision layer's job (Day 4).
- Use the **async** Qdrant client (`AsyncQdrantClient`). The `/chat` path is async and the sync client
  would block the event loop. `fastembed` is sync and CPU-bound, so call it through
  `anyio.to_thread.run_sync` from async code.

### Invariants that are easy to break

1. **Confidence comes from the top *dense* cosine similarity, never from the fused score.**
   Qdrant's RRF fusion returns rank-based scores, so a threshold on a fused score is meaningless
   (PRD Gap #2). `hybrid_search()` therefore returns *both*: the fused hits decide **what** the LLM
   sees, the dense score decides **how confident** we are. Never thread a fused score into a
   confidence threshold.

2. **`qwen3-embedding-8b` is asymmetric.** (The PRD's `nomic-embed-text-v1.5` is no longer served
   on Fireworks.) Documents are embedded **as-is**; queries are wrapped in `QUERY_INSTRUCTION`
   (`Instruct: … 
Query: <text>`). Always use `embed_documents()` / `embed_query()`, never
   `embed_text()` on raw text, and never add the old `search_document:` / `search_query:` prefixes.
   It emits 4096 dims (`embed_dim`). Changing the model means re-running `ingest.py --recreate`;
   `ensure_collections()` refuses to start against a collection of the wrong size.

3. **`data/categories.json` is the single source of truth** for the 10 categories — ids, approval
   rules and required fields — shared with the ticketing service. Never hardcode a category id,
   required-field list or approval flag anywhere in the code.

4. **Thresholds are calibrated, not guessed.** `confidence_high` / `confidence_mid` /
   `router_min_score` come from the 60-query eval set (`eval/eval_set.jsonl`,
   `docs/eval-report-v0.md`). Don't tune them by hand against a single query: change the eval set,
   re-run `eval_run.py` + `eval_report.py`, and record the decision in the report.

5. **Qdrant's sparse vector needs `modifier=models.Modifier.IDF`** to score BM25 correctly. Omitting
   it is silent — search still "works", just badly.

6. **Never answer ungrounded.** No retrieval hits means `MANUAL_ESCALATION` with a fixed reply and
   **no LLM call** — not a best-effort guess.

### Resolution types and decisions

`resolution_type` is one of `RAG`, `AUTO_SR`, `MANUAL_ESCALATION`. The decision layer (PRD Day 4)
emits one of `ANSWER`, `ANSWER_WITH_DISCLAIMER`, `COLLECT_DETAILS`, `RAISE_SR`, `ESCALATE`,
`STATUS_LOOKUP`, first match wins. Only add an enum value when the code can actually emit it —
`AUTO_SR` arrives with the decision layer, not before.

The decision layer ships as a **rule engine first, behind an interface**, with TypeSafe Jev as a
swappable implementation. This is deliberate (PRD risk table): Jev's request shape isn't known until
the Day 4 Playground session, so it must never block the critical path. `TYPESAFE_API_KEY` stays
unused until then.

## Data stores

Each service owns its own Neon Postgres database; they share nothing but the API contract.

- **Qdrant**: `kb_chunks` (named vectors `dense` + `bm25`) and `categories` (dense only).
- **Postgres** (`sr_orchestrator`, PRD Day 6+): `sr_requests`, `decision_logs`, `notifications`.
- **Redis**: `conversation:{user_id}` slot-filling state, 30-minute TTL; also the Celery broker.
  Run dev workers with `--without-gossip --without-mingle --without-heartbeat` — an idle Celery
  worker will otherwise burn the Upstash free-tier command quota.

## Secrets

`.env` is gitignored and holds live credentials; `gitleaks` runs in CI. Never commit it, never paste
key values into code, logs or test fixtures. `FIREWORKS_API_KEY` is required for ingestion and the
answer path; `TYPESAFE_API_KEY` is unused until Day 4–5.
